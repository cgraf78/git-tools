# AGENTS.md

## About

Git subcommands for a GitHub pull-request workflow and proof-based branch
cleanup, one Bash script per command. The man pages hold the detail; keep
new README command sections short, and don't trim the existing reference.

## Layout

- `bin/git-*`: one command per file. Each must be a regular, executable file,
  not a symlink; `test/run` refuses anything else.
- `lib/git-tools-*.sh`: shared code. `inventory` derives the command list
  from `bin/`, `git` runs Git's exec-path binary, `pr`/`pr-snapshot` read
  GitHub through `gh`, and `cleanup` holds the merge and worktree proofs.
- `completions/<cmd>.{bash,zsh,fish}` and `man/man1/<cmd>.1` for every command.
- `share/git-tools/shell.sh`: the sourceable shell integration.
  `share/git-tools/README.md` is its embedding contract.
- `support/`: the install delegate (`install-checkout.sh`) and the launcher
  bootstrap template and sync script.
- `test/<cmd>-test` per command, shared suites, and helpers in `test/lib/`.

## Adding a command

A new `bin/git-<name>` needs all of these, or `test/run` or CI fails:

- three completions; the zsh file's second line is `#description <summary>`;
- a man page that contains the same summary;
- an entry in the `_description_for` table in `test/extras-test`;
- `test/git-<name>-test`;
- rows in `.github/shellcheck-files.txt` for the bin file, the `.bash`
  completion, and the test.

No test checks the README, but each command also gets a README section and
a row in its command table.

## Invariants

- `--porcelain` fields are append-only, and documented exit codes are stable.
  `git cleanup-repo --interface-version` must grow when its porcelain changes.
- Runtime code targets Bash 3.2 and Git 2.29. CI covers these floors only
  partially (a few cases run under macOS's stock `/bin/bash`; no old Git is
  tested), so don't widen what the code relies on.
- The `pr-*` commands pin every GitHub request to the checkout's own
  repository and ignore ambient `GH_REPO`/`GH_HOST`; keep that pinning.

## Testing

- Local: `test/run`, or one suite directly (`test/git-pr-land-test`).
  `test/run` runs 4 suites in parallel (`GIT_TOOLS_TEST_JOBS=1` for
  serial), checks the launcher bootstrap blocks, and runs ShellCheck over the
  inventory's listed programs when `shellcheck` is installed.
- CI: `GIT_TOOLS_SKIP_SHELLCHECK=1 test/run` on the shared shell matrix
  (Linux distros, macOS, WSL, Termux; profiles `base,jq`), plus a separate
  ShellCheck job. CI has no fish or `git-absorb`, and zsh only on macOS, so
  those completion syntax checks and the absorb rewrite cases mostly run
  locally.

## Test isolation

- Command suites use `test/lib/test-temp.sh` for temp dirs and
  `gt_test_git_isolate` (`test/lib/hermetic-git.sh`) to move HOME and XDG
  under the suite root, with `GIT_CONFIG_NOSYSTEM=1` and a private
  `GIT_CONFIG_GLOBAL`. A few suites set the same variables inline.
- `GIT_TOOLS_TEST_PATH_GIT=1` makes the commands use the fake `git` on
  `PATH` instead of Git's exec-path binary. Suites put a fake `gh` on `PATH`;
  never let a test reach GitHub.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale rows;
  local `test/run` does not detect this. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`
  from a cgraf78/actions checkout at the SHA in `.github/cgraf78-actions.lock`.
- `install.sh` is generated by the cgraf78/actions checkout installer and
  byte-checked by the `cgraf78/actions sync` job; never hand-edit it. Install
  behavior lives in the repo-owned `support/install-checkout.sh`. After
  changing `scripts/checkout-installer.conf`, run
  `consumer-ci/sync.sh <this checkout>` from cgraf78/actions at the locked SHA.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@<sha>`
  move together, only via `consumer-ci/sync.sh`.
- The `# BEGIN/END GENERATED LAUNCHER BOOTSTRAP` blocks in `bin/*` come from
  `support/launcher-bootstrap.sh.template`. Edit the template, then run
  `support/sync-launcher-bootstrap`.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename
  it.
